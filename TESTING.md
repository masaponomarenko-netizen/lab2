# Чек-лист перевірки лабораторної №2

Перед перевіркою запусти застосунок:

```bash
cd /Users/masaponomarenko/RiderProjects/lab2
dotnet run --project ConferencesLab/ConferencesLab.csproj -f net10.0-maccatalyst
```

---

## 1. Завантаження вбудованого файлу

- [ ] Натиснути **«Приклад XML»**.
- [ ] У блоці «Файл» має з'явитися `conferences.xml (вбудований приклад)`.
- [ ] У рядку «Дані» має бути: `Конференцій: 10 · різних атрибутів: 9`.

**Що це доводить:** XML читається, каталог атрибутів будується.

---

## 2. Динамічне підвантаження атрибутів і значень

- [ ] Відкрити список **«Атрибут»**. Там мають бути:
      `category, currency, fee, format, id, language, seats, title, website`.
- [ ] Вибрати `category`. У списку **«Значення»** мають з'явитися 10 різних тематик.
- [ ] Вибрати `fee`. У списку значень має бути лише 6 варіантів
      (бо не всі конференції мають атрибут `fee`).
- [ ] Вибрати `seats`. Має бути лише 3 варіанти.

**Що це доводить:** списки будуються з реального файлу, а не зашиті в код;
різна кількість атрибутів обробляється коректно.

---

## 3. Однаковий результат для трьох стратегій

Для кожного запиту нижче перевір **усі три стратегії**:
`SAX API`, `DOM API`, `LINQ to XML`.

| Атрибут | Значення | Очікувано |
|---|---|---|
| `category` | `Artificial Intelligence` | 1 конференція |
| `format` | `hybrid` | 2 конференції |
| `fee` | `1200` | 1 конференція |
| `language` | `English` | 3 конференції |
| `currency` | `EUR` | 2 конференції |
| `seats` | `250` | 1 конференція |

- [ ] Кількість знайдених збігається для SAX, DOM і LINQ.
- [ ] Назви знайдених конференцій однакові.
- [ ] У полі результату видно:
      стратегію, згенерований запит, кількість і час виконання.

**Що це доводить:** шаблон «Стратегія» працює, всі три API дають однаковий результат.

---

## 4. Пошук за ключовим словом

Спочатку натисни **«Clear»**, щоб скинути атрибут, потім введи слово
в поле «Ключове слово» і натисни «Знайти».

| Ключове слово | Очікувано |
|---|---|
| `київ` | 3 конференції |
| `КИЇВ` | 3 конференції (регістр не важливий) |
| `english` | 3 конференції |
| `devops` | 2 конференції |
| `конференц` | 1 конференція |
| `zzzz` | 0 (написано «Нічого не знайдено») |

**Що це доводить:** пошук іде не лише по атрибутах, а й по вкладеному тексту;
регістр не має значення.

---

## 5. Комбінований запит

- [ ] Атрибут `category` = `Software Engineering`.
- [ ] Ключове слово `devops`.
- [ ] Натиснути «Знайти».

**Очікувано:** 1 конференція — «Інженерія програмного забезпечення 2026».

**Що це доводить:** динамічний запит комбінує умови (атрибут + ключове слово).

---

## 6. Кнопка Clear

- [ ] Спочатку виконати будь-який пошук, щоб поле результату було заповнене.
- [ ] Натиснути **«Clear»**.
- [ ] Поле результату має стати порожнім.
- [ ] Поле «Ключове слово» має очиститися.
- [ ] Вибір атрибута і значення має скинутися.
- [ ] Статус має показати, що параметри очищено.

**Що це доводить:** вимога про кнопку Clear виконана.

---

## 7. Трансформація XML → HTML

- [ ] Натиснути **«Трансформувати в HTML»**.
- [ ] Має відкритися браузер з HTML-звітом.
- [ ] У звіті має бути 10 карток конференцій.
- [ ] Видно назву, тематику, дати, організатора, місце, вартість тощо.
- [ ] Внизу є дата формування звіту.

**Що це доводить:** XSLT-трансформація працює, HTML будується за XSL-шаблоном.

---

## 8. Вибір власного файлу

- [ ] Скопіювати `ConferencesLab/Resources/Raw/conferences.xml` на робочий стіл.
- [ ] Натиснути **«Обрати XML…»**.
- [ ] Вибрати цей файл.
- [ ] Перевірити, що завантажилися ті самі 10 конференцій.

**Що це доводить:** програма працює не лише з вбудованим прикладом.

Якщо діалог вибору файлу не відкривається — для захисту достатньо кнопки
«Приклад XML», але бажано показати і вибір власного файлу.

---

## 9. Підтвердження виходу

- [ ] Натиснути **«Вихід»**.
- [ ] Має з'явитися діалог:
      «Чи дійсно ви хочете завершити роботу з програмою?»
      з кнопками **«Так»** і **«Ні»**.
- [ ] Натиснути **«Ні»** — застосунок має залишитися відкритим.
- [ ] Знову натиснути «Вихід» → **«Так»** — застосунок має закритися.

**Що це доводить:** вимога про підтвердження виходу виконана.

---

## 10. Що показати викладачу

1. XML-файл: різна кількість атрибутів у `<conference>`.
2. Три класи-стратегії та інтерфейс `IXmlSearchStrategy`.
3. Один запит — три стратегії — однаковий результат.
4. Динамічні списки атрибутів/значень.
5. XSLT-файл і готовий HTML-звіт.
6. Кнопки Clear і Вихід.

---

## Якщо щось не працює

- Порожній список «Атрибут» — спочатку натисни «Приклад XML».
- Порожнє вікно при виборі атрибута — файл ще не завантажений.
- Невидимий текст у полях — перезапусти застосунок після останньої збірки.
- Завис діалог вибору файлу — `killall ConferencesLab` і запусти заново.
